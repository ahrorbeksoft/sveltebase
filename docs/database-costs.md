# Database operation ledger

Sveltebase separates source database work, durable broker/idempotency work, and local IndexedDB work. A query call is not a billable document read. Adapters must report provider measurements separately: a query returning 500 documents can be one call and 500 billable reads, and a retried transaction can bill more than its final attempt.

| Operation                                                | Source database                                                                                       | Broker / idempotency storage                           | Local IndexedDB                                                          |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| Signed cookie verification, ordinary auth initialization | 0 reads, 0 writes                                                                                     | 0                                                      | 0                                                                        |
| Initial channel subscription                             | One application snapshot operation; record returned rows and actual provider reads                    | Optional cursor/log state                              | Confirmed snapshot + materialized optimistic view + cursor               |

| Create                                                   | Application write and validation; canonical returned row avoids refetch                               | Atomic mutation outcome record                         | One transaction for optimistic row + outbox sequence and entry           |
| Update/delete                                            | At most one explicit original-row load in generic policy path; reuse for policy, mutation and routing | Atomic outcome record                                  | One transaction for optimistic view + outbox                             |
| Committed mutation replay                                | 0 repeated domain writes                                                                              | Dedupe lookup, including transaction retries           | Acknowledgment cleanup + pending replay                                  |

Record query calls, rows/documents read, source writes, transaction attempts, broker reads/writes, replay hits, fetches, snapshot rows and resets. Do not record credentials or row contents. Framework hooks can observe callback invocations and returned rows; only the provider adapter can measure query plans, read amplification, retries, and billing units. A callback that performs additional work must report that work.

## Catch-up and idempotency adapters

Native committed change streams can avoid a second domain change-log write. Otherwise the application must commit its row write, an ordered change-log record (a tombstone for delete), and the mutation result in the same transaction. The record must contain enough trusted routing information to deliver a delete without looking up a deleted row. Cursors must be committed, monotonically ordered within the routing scope, and backed by indexed bounded queries. Retention must reject expired cursors and request a full reset. Never fabricate a timestamp cursor from a client clock.

Atomic idempotency storage is an application contract. A broker memory cache or a post-write outcome record cannot prevent a second domain write after a crash. Choose retention to cover the maximum supported offline replay interval; after eviction, old IDs cannot be safely treated as new without an application policy. Transactions may retry and bill each attempt. Cross-store transactions require a transactional outbox or an equivalent provider-supported protocol; there is no generic exactly-once guarantee across unrelated stores.

## Examples

For a canonical row delivered to 1 or 1,000 already-authorized subscribers, the default routing path performs no additional source reads. There are respectively 1 or 1,000 socket deliveries. Application callbacks must not query once per recipient. A notification that asks all 1,000 clients to resync can cause 1,000 source queries and is reserved for explicit invalidation.

An initial snapshot of 500 rows for 1,000 independent visibility scopes can cost 1,000 queries and 500,000 document reads. Sharing concurrent identical client requests removes redundant operations within compatible context/channel/request shapes; it does not justify caching authorization across users. Permission revocation takes precedence over reuse.

An offline client with 20 committed missing changes should use bounded indexed catch-up of those changes, including tombstones. If its cursor has expired, a 500-row snapshot can be necessary. Ten pending mutations can add ten domain writes, ten log writes, and ten idempotency-result writes before transaction/provider overhead. Replaying all ten after acknowledgments are lost adds dedupe reads but no repeated domain writes under the atomic adapter contract.
